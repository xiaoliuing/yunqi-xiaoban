# 孕期小伴 —— 设计文档

日期：2026-10-14
状态：待用户审阅

## 1. 背景与目标

妻子怀孕，白天常独自在家，每天面临三个问题：

1. 今天吃什么？
2. 这个能不能吃 / 这个症状正常吗？
3. 下次产检是什么时候、要准备什么？

目标：做一个手机上打开即用的孕期助手，打开首页就能回答以上三个问题，覆盖全部孕周的注意事项、营养补充建议和产检提醒。

非目标（第一版不做）：双人账号与数据同步、服务器推送通知、产检报告存档、社区/社交、心情记录。

## 2. 关键决策

| 决策 | 选择 | 理由 |
| --- | --- | --- |
| 形态 | PWA（手机网页，可添加到桌面） | 开发最快，iPhone/Android 都能用，无需上架审核 |
| 数据 | 仅存本地（IndexedDB），提供导出/导入备份 | 无服务器、无隐私风险、上线最快 |
| 三餐推荐 | 内置食谱库为主 + 可选「AI 问一问」 | 日常离线可用、内容可控；AI 处理个性化问题 |
| 提醒 | 产检日程导出为 `.ics`，由系统日历提醒；应用内显示倒计时 | 纯本地 PWA 无法在后台准时推送，系统日历最可靠 |
| 技术栈 | Vue 3 + Vite + TypeScript + vite-plugin-pwa | 用户熟悉 Vue |
| 部署 | 静态托管（Cloudflare Pages 或同类） | 免费，HTTPS 满足 PWA 要求 |

## 3. 第一版功能范围

核心：
- 首次设置
- 今日卡片
- 今日三餐推荐（可「换一道」）
- 「能不能吃」查询
- 产检日程 + 一键导入日历
- 40 周孕周时间轴
- AI 问一问（可选，需用户自填 API Key）

附加：
- 补剂打卡（叶酸、铁、钙、DHA）
- 体重记录与增长曲线
- 一周食谱 + 购物清单
- 危险信号速查
- 孕晚期工具：胎动计数、宫缩计时、待产包清单（孕 28 周起显示）

## 4. 页面结构

### 4.1 首次设置（约 1 分钟）
- 预产期 或 末次月经日期（二选一，另一个自动推算：预产期 = 末次月经 + 280 天）
- 孕前身高、体重（用于 BMI 和体重增长范围）
- 忌口与偏好：多选（不吃辣、不吃羊肉、海鲜过敏、素食等）+ 自定义食材
- 可选：医院名称（写入日历事件的地点）

所有字段之后都可以在「我的 → 设置」中修改。

### 4.2 底部四个标签页

**今天**
- 顶部：孕 X 周 + Y 天、孕期阶段、距预产期天数、宝宝大小（水果类比）
- 今日三餐：早餐 / 午餐 / 晚餐 / 加餐，每道显示营养标签，可「换一道」，可标记「已吃」
- 补剂打卡：当日应服补剂列表，点一下打卡；钙和铁提示错开服用
- 下一次产检卡片：名称、建议日期、倒计时、注意事项（空腹/憋尿/携带物品）
- 本周注意事项（来自孕周内容）

**吃**
- 「能不能吃」搜索：绿（可以吃）/ 黄（适量或注意做法）/ 红（避免），附原因和建议
- 一周食谱：未来 7 天的三餐，可逐道替换
- 购物清单：由一周食谱生成，按类别分组，可勾选
- AI 问一问：自由提问（例如「今天孕吐吃不下，有什么推荐」）

**孕期**
- 40 周时间轴：默认定位到当前周，可前后翻看
- 产检日程：全部产检列表，可修改实际预约日期，「导入日历」按钮
- 危险信号速查

**我的**
- 体重：记录体重，曲线叠加按孕前 BMI 计算的推荐范围
- 孕晚期工具（孕 28 周起显示）：胎动计数、宫缩计时、待产包清单
- 设置：个人资料、忌口、AI Key、导出/导入备份、关于与免责声明

## 5. 代码结构

```
src/
  content/        只读内容数据（TS 模块，随应用打包）
  core/           纯计算逻辑，不依赖 Vue，单元测试重点
  db/             IndexedDB 读写（Dexie）
  ai/             AI 问一问的请求与安全包装
  stores/         Pinia：profile、记录类数据
  views/          四个标签页 + 首次设置
  components/     卡片、列表等可复用组件
```

### 5.1 内容数据（`src/content/`）

| 文件 | 内容 | 规模 |
| --- | --- | --- |
| `weeks.ts` | 第 4–40 周：宝宝大小与发育、妈妈变化、本周注意事项 | 37 条 |
| `checkups.ts` | 产检项目：孕周范围、名称、目的、是否空腹/憋尿、携带物品 | 约 15 条 |
| `recipes.ts` | 菜谱：名称、餐次、适用孕期、营养标签、食材（含分类）、做法、过敏原/忌口标签 | 约 100 道 |
| `foods.ts` | 「能不能吃」词条：名称、别名、档位、原因、建议 | 约 150 条 |
| `redflags.ts` | 危险信号：症状、级别（立即就医 / 尽快就诊）、说明 | 约 15 条 |
| `nutrition.ts` | 各孕期营养重点、每日目标、补剂建议 | 3 个阶段 |

内容来源：《中国居民膳食指南（2022）》孕期妇女膳食指南、《中国居民膳食营养素参考摄入量（2023 版）》、《妊娠期妇女体重增长推荐值标准》（WS/T 801-2022），以及国内常规产检安排。具体数值在整理内容时逐条核对来源。

营养要点（整理内容时按上述来源核对具体数值）：
- 叶酸：备孕至孕早期每天补充 400 μg，可延续整个孕期
- 碘：使用加碘盐，每周吃 1–2 次海带、紫菜等海产品
- 铁：孕中、晚期需要量增加，每周吃 1–2 次动物血或肝脏，每天吃适量红肉
- 钙：孕中、晚期每天喝奶 300–500 g
- DHA：每周吃 2–3 次鱼类，优先选低汞鱼
- 能量：孕早期不额外增加；孕中期、孕晚期按 DRIs 2023 分别适量增加

产检安排（默认，用户可修改实际日期）：

| 孕周 | 项目 | 备注 |
| --- | --- | --- |
| 6–8 | B 超确认宫内孕、胎心 | |
| 11–13⁺⁶ | NT 检查、建档 | 建档抽血通常需空腹 |
| 15–20⁺⁶ | 唐氏筛查（或 12–22⁺⁶ 周 NIPT 无创） | 按医院安排 |
| 20–24 | 系统超声（大排畸） | |
| 24–28 | 糖耐量试验（OGTT） | 需空腹，约 2–3 小时 |
| 28–36 | 每 2 周一次常规产检；30–32 周生长发育 B 超 | |
| 35–37 | B 族链球菌（GBS）筛查 | |
| 36 起 | 每周一次产检 + 胎心监护 | |

体重增长推荐范围（WS/T 801-2022，按孕前 BMI）：

| 孕前 BMI | 总增重 |
| --- | --- |
| < 18.5 | 11–16 kg |
| 18.5–23.9 | 8–14 kg |
| 24.0–27.9 | 7–11 kg |
| ≥ 28.0 | 5–9 kg |

### 5.2 计算逻辑（`src/core/`）

每个模块只导出纯函数，输入输出明确：

- `pregnancy.ts`
  - `fromLmp(lmp) → dueDate`，`fromDueDate(dueDate) → lmp`
  - `getStatus(dueDate, today) → { week, day, trimester, daysToDue, inRange }`
  - 孕期划分：孕早期 < 14 周，孕中期 14–27⁺⁶ 周，孕晚期 ≥ 28 周
- `mealPlanner.ts`
  - `planDay({ trimester, exclusions, recentRecipeIds, seed }) → DayPlan`
  - `swapDish(plan, slot, context) → DayPlan`
  - `planWeek(...) → DayPlan[]`
  - 规则：先排除含忌口/过敏原的菜，再按适用孕期筛选，避开近 7 天推荐过的菜，按当前孕期营养重点（如孕中期优先「补铁」「补钙」）加权随机选择；相同 seed 输出相同结果，方便测试，也保证同一天反复打开看到的推荐一致
- `weightGain.ts`
  - `bmi(heightCm, weightKg)`
  - `recommendedRange(preBmi, week) → { min, max }`（孕早期增重按 0–2 kg 处理，之后线性插值到总增重范围）
  - `assess(preBmi, week, currentWeight) → 'low' | 'normal' | 'high'`
- `checkupSchedule.ts`
  - `buildSchedule(dueDate, overrides) → Checkup[]`：建议日期取孕周范围的起始日，用户设置的实际日期优先
  - `nextCheckup(schedule, today)`
- `ics.ts`
  - `toIcs(checkups, { location }) → string`：每项产检为一个全天事件，带提前 1 天的提醒（VALARM），描述中写入注意事项
- `shoppingList.ts`
  - `fromWeekPlan(days) → { category, items: { name, amount }[] }[]`：同名食材合并
- `kickCounter.ts`、`contractionTimer.ts`
  - 胎动：每次计数时段内，记录 5 分钟内的连续胎动为 1 次；2 小时内少于 10 次时提示及时就医
  - 宫缩：记录开始和结束时间，计算间隔和持续时间；连续 1 小时内间隔 ≤ 5 分钟、每次持续 ≥ 1 分钟（5-1-1 规律）时，提示准备去医院

### 5.3 本地数据（`src/db/`）

Dexie 表：
- `profile`（单条）：预产期、孕前身高体重、忌口、医院、AI 设置
- `mealLogs`：日期 → 当日三餐（菜谱 id）及「已吃」状态
- `supplementLogs`：日期 + 补剂 → 已打卡
- `weights`：日期 → 体重
- `kickSessions`、`contractions`：时间戳记录
- `checkupOverrides`：产检 id → 实际日期 / 已完成
- `bagChecklist`：待产包条目 → 已勾选

导出：全部表序列化为一个 JSON 文件下载；导入：校验版本号后覆盖写入，导入前需二次确认。

### 5.4 AI 问一问（`src/ai/`）

- 用户在设置中填写兼容 OpenAI 格式的接口地址、API Key、模型名，只保存在本机；不填写则隐藏入口
- 系统提示词注入当前孕周、孕期阶段、忌口，并明确要求：不推荐 `foods.ts` 中标红的食物，涉及症状一律建议就医
- 回答返回后，用 `foods.ts` 中标红词条做一次关键词扫描，命中时在回答上方显示警示
- 每条回答下方固定显示「AI 回答仅供参考，请以医生意见为准」
- 网络错误、Key 无效时显示明确错误提示，不影响其他功能

## 6. 边界情况与错误处理

- 孕周 < 4 或 > 42：今日卡片显示提示（「请确认预产期设置」或「已过预产期，请遵医嘱」），其他功能照常使用
- 过滤后可选菜谱不足：先放宽「近 7 天不重复」，再放宽孕期匹配，但绝不放宽忌口和过敏原过滤；仍然不足时该餐次显示「暂无合适推荐」
- 未完成首次设置：所有页面重定向到设置流程
- IndexedDB 不可用（如部分浏览器的隐私模式）：顶部提示「数据无法保存」，功能以内存模式运行
- 导入备份文件格式错误或版本不符：拒绝导入并说明原因，不改动现有数据
- iPhone 用户：首次打开时引导「分享 → 添加到主屏幕」

## 7. 安全与免责

- 每个内容页底部显示「仅供参考，请以医生意见为准」
- 危险信号页的「立即就医」项置顶并用醒目颜色，附「拨打 120」按钮（`tel:120`）
- 应用不收集、不上传任何数据（AI 问一问除外，仅发送问题和孕周信息到用户自己配置的接口）

## 8. 测试

- Vitest 单元测试覆盖 `src/core/` 全部函数，包括：预产期换算、孕周边界（13⁺⁶ / 14⁺⁰、27⁺⁶ / 28⁺⁰）、三餐推荐的忌口过滤与确定性、换一道不换回原菜、体重范围插值、`.ics` 格式（可被日历解析）、购物清单合并、5-1-1 判定
- 内容完整性测试：第 4–40 周每周都有内容；每个孕期每个餐次至少 8 道可选菜；菜谱食材不包含 `foods.ts` 中标红的条目；产检孕周范围不重叠且有序
- 组件测试（Vue Test Utils）：首次设置流程、今日卡片渲染、「换一道」交互
- 手动验收：iPhone Safari 和 Android Chrome 上完成「添加到桌面 → 离线打开 → 导入日历」
